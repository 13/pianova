# Pianova Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A web app that teaches piano from zero through 24 authored lessons played on a note highway with a MIDI keyboard.

**Architecture:** DOM-free logic modules (chart, judge, session, progress, curriculum) with unit tests, driven by a thin browser layer (Web MIDI + computer keys in, Web Audio synth out, one Canvas 2D highway, vanilla-DOM screens). One clock: `AudioContext.currentTime`.

**Tech Stack:** Vite, TypeScript (strict), Vitest, `@tonejs/midi`. No UI framework.

**Spec:** `docs/superpowers/specs/2026-11-20-pianova-design.md`

## Global Constraints

- Chromium only; served from localhost; no network requests after load (no CDN fonts/samples).
- Lesson notes stay within C3–C5 (MIDI 48–72); lesson chords ≤ 3 notes.
- Timing windows: perfect ±50 ms, good ±120 ms. Weights: perfect 1.0, good 0.7.
- Accuracy = weighted hits / (total notes + wrong presses). Stars: pass threshold (default 0.80) → 1, 0.90 → 2, 0.97 → 3.
- Units 1–2 perform steps use `pitch` judging; Units 3–6 use `timed`.
- No fail-out; progress is never lost. Storage: one versioned blob in `localStorage` key `pianova.v1`, backup key `pianova.backup`.
- Original visual identity; nothing copied from Rocksmith+.
- Logic modules import nothing from the DOM.

## Review Focus

1. Tab hidden mid-song (rAF stops, clock keeps running) → session must pause, not dump a wall of misses. (Task 3 test: large `update` gap is clamped; Task 9: pause on `visibilitychange`.)
2. MIDI note-on with velocity 0 is a note-off; running a note twice without release must not double-hit. (Task 2 test: second press of same pitch in window is `wrong`-free only if another matching note is pending; Task 7.)
3. Imported `.mid` with zero notes, tempo changes, or notes outside 21–108 → clear error / clamped, no crash. (Task 6 tests.)
4. `localStorage` missing, full, or holding garbage → app still runs with in-memory progress. (Task 4 tests.)
5. Loop range reversed or beyond the chart end → normalised. (Task 3 test.)

### Task 2: Judge

**Files:** `src/judge/judge.ts`, `tests/judge.test.ts`

**Produces:**
```ts
type Grade = 'perfect' | 'good' | 'miss'
interface JudgeNote { pitch: number; time: number; hand: Hand }       // seconds
type PressResult = { kind: 'hit'; index: number; grade: Grade; offsetMs: number } | { kind: 'wrong'; pitch: number }
interface Summary { total: number; perfect: number; good: number; miss: number; wrong: number; accuracy: number;
  streak: number; bestStreak: number; meanOffsetMs: number; missedPitches: Record<number, number> }
class Judge {
  constructor(notes: JudgeNote[], mode: 'timed' | 'pitch')
  press(pitch: number, time: number): PressResult   // timed: nearest unjudged same-pitch note within ±0.120 s
  advance(time: number): number[]                   // timed: indexes newly missed (time > note.time + 0.120)
  pendingGroup(): number[]                          // pitch mode: unjudged indexes of the earliest unfinished start time
  done(): boolean
  summary(): Summary
}
starsFor(accuracy: number, pass = 0.8): 0 | 1 | 2 | 3
```
Pitch mode: a press matching a note in `pendingGroup()` is a `perfect` hit with offset 0; anything else is `wrong`. Accuracy: per-note score (1 / 0.7 / 0), but every note in a chord group (same `time`) takes the group's minimum; divided by `total + wrong`; 0 when total is 0. `meanOffsetMs` over timed hits only (negative = early).

- [ ] Tests: +40 ms → perfect, −100 ms → good, +130 ms → wrong; `advance` past window marks miss once; chord with one member missed scores 0 for all members; wrong presses lower accuracy (4 perfect + 1 wrong = 0.8); two same-pitch notes 100 ms apart each take one press; a third press is wrong; pitch mode ordering and chord group; streak resets on miss and wrong; `starsFor(0.79)=0, 0.8=1, 0.9=2, 0.97=3`.
- [ ] Implement; tests pass; commit.

### Task 3: Session

**Files:** `src/session/session.ts`, `tests/session.test.ts`

**Produces:**
```ts
type Mode = 'demo' | 'wait' | 'timed'
interface SessionOptions { chart: Chart; mode: Mode; scoring: 'none' | 'pitch' | 'timed'; hands: Hand[];
  tempoScale?: number; loop?: { fromBar: number; toBar: number }; countIn?: boolean; latencyMs?: number }
interface SessionEvents { autoNote(pitch: number, on: boolean, hand: Hand): void; click(accent: boolean): void;
  judged(noteIndex: number, grade: Grade, offsetMs: number): void; wrong(pitch: number): void; finished(): void; looped(): void }
class Session {
  constructor(opts: SessionOptions, events: Partial<SessionEvents>)
  readonly chart: Chart
  beat: number                         // current position, negative during count-in
  state: 'idle' | 'running' | 'paused' | 'finished'
  noteState: ('pending' | Grade)[]     // by chart note index, for the renderer
  start(now: number): void; pause(now: number): void; resume(now: number): void
  update(now: number): void            // call every frame
  press(pitch: number, now: number): void; release(pitch: number): void
  summary(): Summary
  secondsPerBeat: number
}
```
- `timed`: beat follows the clock; count-in of one bar with clicks when `countIn`; clicks on every integer beat; finishes one beat after the last note ends.
- `wait`: beat advances at tempo but stops at the start beat of the earliest pending group in the selected hands; resumes when that group is fully pressed. No clicks.
- `demo`: all hands auto-played, nothing judged.
- Hands not in `hands` are auto-played via `autoNote` (on at start, off at end) in every mode.
- `scoring: 'none'` → presses never produce `wrong`. `'pitch'` uses Judge pitch mode (requires `wait`). `'timed'` uses Judge timed mode with `press` time minus `latencyMs`.
- Loop: bars are 1-based inclusive; reversed or out-of-range values are swapped/clamped; at loop end → reset judge and note state, emit `looped`, never `finished`.
- `update` gap > 0.25 s is treated as a pause of that length (clock shifted), so hidden tabs don't produce misses.

- [ ] Tests (fake `now`): timed run with perfect presses finishes with accuracy 1; count-in emits `beatsPerBar` clicks before beat 0; wait mode holds at a note until pressed then moves on; chord in wait needs all keys; left hand auto-played when `hands: ['R']` and not counted in summary total; tempoScale 0.5 doubles note times; loop 2..1 normalises to 1..2 and loops; 5 s gap between updates causes no misses; latency 100 ms shifts judging.
- [ ] Implement; tests pass; commit.

class Synth { ctx: AudioContext; now(): number; fromPerf(ts: number): number; resume(): Promise<void>;

### Task 8: Highway renderer

**Files:** `src/render/highway.ts`

**Produces:**
```ts
class Highway { constructor(canvas: HTMLCanvasElement);
  setChart(chart: Chart, opts: { labels: boolean }): void    // picks visible range: chart range padded to whole octaves, min 2
  setHeld(pitches: Set<number>): void; flash(pitch: number, kind: Grade | 'wrong'): void;
  draw(beat: number, noteState: ('pending' | Grade)[], highlight?: Set<number>): void; resize(): void }
```
Perspective: for a note `t` beats ahead (look-ahead 8 beats), `p = (1−d)/(1+1.6d)` with `d = t/8`; `y = horizon + (hitY−horizon)·p`, `x = cx + (keyX−cx)·(0.32 + 0.68p)`. Right hand and left hand colours distinct; finger number and note name on each bar when it is close; hit notes fade, missed notes dim.
